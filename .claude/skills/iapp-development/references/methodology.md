# 探针方法

## 铁律

1. **先探针后开发**：任何「应该能行」都无依据；不确定就写探针页。
2. **双证据**：屏幕可判读现象 + logcat 原文
   ```
   adb logcat -d -v time 'ygs:V' 'System.err:V' '*:S'
   ```
   打包环境没有 `ygs` 输出，只能把结果写到界面控件。
3. **结论分级**：✅实测 / ⚠推测 / ❓未知；`null` / `false` / `0` 必须设锚点。
4. **账本**：跨运行比较用追加式记录（写进你自己的证据文件，文件名自定）。
   账本是测量链的一部分，不是事后整理：它固定前提（设备/版本/density/批次）、零点锚点和历史基线，且只追加不覆盖——能随手改的记录，读数就不可信。
5. **一页一问**：一页只回答一个问题，但一轮可以写多页。
6. **隔离失败**：每个待测写法放独立 `.mjava` 模块，坏一个不连坐；会中断事件的（匿名类）放最后。
7. **版本前提**：结论写清 API/版本，例如「API 28 上匿名接口实现可用」，不要外推到其它版本。
8. **参数个数探测**：事件回调可以写 0/1/2 参重载（`onSel()` / `onSel(Object p)` / `onSel(Object p, Object o)`），iApp 注入几个参数就命中哪个；命中哪档本身就是读数。

## null / false / 0：先判“测没测”，再判“有没有”

`null` / `false` / `0` 本身不能区分“没有”和“没测过”，按三态记录：

1. **没测过**：探针没执行、事件没触发、页面没加载。判据是**执行痕迹**：每步先打 `i.syso("R-xxx=...")` 或前后哨兵；日志缺行就是没测到，账本写“未执行”，不要写 `null`。
2. **测了但没有**：执行痕迹在，读数确实是空值。再用正负对照确认：
   - 正对照：同一条路径上，一个已知存在/为真/非零的对象必须读出非空值，证明探针机制本身是通的。
   - 负对照：一个已知不存在的 id/键/分支必须读出同样的空值，证明空值确实代表“没有”。
3. **测了且有值**：正常记录，并注明 `0` / `false` 是否可能是合法值（索引 0、size 0、未选中都可能是真实状态）。

实现要点：

- 初值用唯一哨兵（如 `"__UNSET__"`、`Integer.MIN_VALUE`），不要用 `null` / `0` / `false` 当“未设置”。
- 双通道：屏幕汇总 + logcat；两边都缺 = 没测过。
- `findViewById(id)` 返回 null 时，先查同树里一个已知 id；已知 id 也 null → 页面/探针问题，不是“控件不存在”。
- 事件没回调时，先在绑定处打日志；绑定日志都没有 → 没测过；绑定了但没回调 → 触发方式或事件名问题。

## 静态分析 vs 探针

| | 静态分析（dexdump / APK / 源码） | 探针页 |
|---|---|---|
| 回答 | **有什么**：类/方法/字段/签名/重载/可见性/是否被裁剪；**怎么连**：调用图、父加载器、资源、注册表；结构上可不可能 | **运行时实际怎样**：是否执行、返回值、异常、回调顺序与参数、时序、UI 效果、版本/设备差异 |
| 不能回答 | 运行时值、副作用、时序、生命周期、权限、渲染 | 为什么（根因/实现）、未触发的分支、全量行为 |
| 结论地位 | 假设与排除法 | 判决与证据 |

用法：先静态缩小范围、排除“根本不存在”的写法；再用探针证实或证伪。静态说“有”不等于运行时能用，静态说“没有”通常可以直接放弃。

## 探针结构

```
page.iyu        一页：控件 + loading 里按序 call（不写 syso）
m_xxx.mjava     一个写法一个模块
i.syso("R-xxx=" + 结果)   每步一行，便于定位停在哪
```

> 早期探针在 `.iyu` 里用过 `syso`；白名单收紧后已全部下沉到 mjava。

- 屏幕也给一份结果：把汇总写进 TextView，打包/无日志时仍可判读
- 先跑安全项，再跑可能中断的项
- 报错后是否继续，是判断错误类型（`MJavaErr` / `JavaErr` / `YuErr`）的关键

## 运行前后

- 改源码前 `am force-stop`（iApp 以内存为准）
- 运行由用户操作，Claude 不代点界面
- 运行后先拉 logcat，再截图；两处对不上时以屏幕为准并记录差异
